### 1.1 코어/셸 경계 (가장 중요한 계약)

코어는 **시간을 모른다.** 멀티탭 타임아웃은 본질적으로 시간 의존 동작이지만, 이를 코어에 넣으면 플랫폼별 타이머 구현 차이가 곧 조합 결과 차이로 이어진다.

따라서: **셸이 타이머를 소유하고, 만료 시 코어에 `TIMEOUT`이라는 가상 키를 보낸다.** 코어에게 `TIMEOUT`은 다른 키와 똑같은 입력이며, 그 의미는 "멀티탭 세션을 종료하라"뿐이다.

이 설계의 결과로 **테스트 벡터가 완전히 결정적**이 된다. `["K4","TIMEOUT","K4"]`는 5개 플랫폼 어디서든 반드시 `ㄱㄱ`이다.

## 3. 모음 조합 오토마타

21개 중성 전체가 3개 키(`1`=ㅣ, `2`=ㆍ, `3`=ㅡ)의 조합으로 생성된다. 상태 전이도:

![모음 오토마타](../assets/vowel-automaton.svg)

### 3.1 미완성 상태 (Pending State)

`ㆍ`와 `ㆍㆍ`는 **화면에 출력되지 않는 중간 상태**다. 현대 한글에 아래아(ㆍ)가 없기 때문이다.

이 구분은 구현상 필수다. 사용자가 `ㄱ` → `ㆍ`를 누른 시점에 화면에는 `ㄱ`만 보여야 하며, `가`나 `고`로 성급히 확정하면 안 된다. 코어의 `preedit()`는 pending 상태의 모음을 빈 문자열로 취급한다.

### 3.2 3타 순환

`ㆍ`를 세 번 누르면 다시 1개 상태로 돌아간다(`ㆍ → ㆍㆍ → ㆍ`). 아래아 3개는 쓰이지 않으므로 순환시켜 오입력을 복구 가능하게 한다.

### 4.2 기능키 대체 경로 (결정적)

멀티탭은 연속 동일 키에서 모호하다. 획추가(`*`)·쌍자음(`#`)은 **타임아웃 없이** 같은 결과에 도달하는 경로를 제공한다.

| 목표 | 기능키 경로 | 결과 | 멀티탭 경로 |
|---|---|---|---|
| ㅋ | `4*` | 카 | `44` |
| ㄲ | `4#` | 까 | `444` |
| ㅌ | `6*` | 타 | `66` |
| ㄸ | `6#` | 따 | `666` |
| ㅍ | `7*` | 파 | `77` |
| ㅃ | `7#` | 빠 | `777` |
| ㅎ | `0*` | 하 | `88` |
| ㅆ | `8#` | 싸 | `888` |
| ㅊ | `9*` | 차 | `99` |
| ㅉ | `9#` | 짜 | `999` |
| ㄷ | `5*` | 다 | `6` |
| ㅈ | `8*` | 자 | `9` |

획추가는 훈민정음 가획 원리를 따른다: ㄱ→ㅋ, ㄴ→ㄷ→ㅌ, ㅁ→ㅂ→ㅍ, ㅅ→ㅈ→ㅊ, ㅇ→ㅎ.

|---|---|---|---|
| ㄳ | 갃 | `41248` | 5 |
| ㄵ | 갅 | `41259` | 5 |
| ㄶ | 갆 | `412588` | 6 |
| ㄺ | 갉 | `412554` | 6 |
| ㄻ | 갊 | `4125500` | 7 |
| ㄼ | 갋 | `412557` | 6 |
| ㄽ | 갌 | `412558` | 6 |
| ㄾ | 갍 | `4125566` | 7 |
| ㄿ | 갎 | `4125577` | 7 |
| ㅀ | 갏 | `4125588` | 7 |
| ㅄ | 값 | `41278` | 5 |

**중요**: 획추가·쌍자음 키가 겹받침 상태에서 눌리면 **마지막 성분에만** 적용된다.
예: `밟` = `ㅂㅏ` + `ㄹ` + `ㅂ` 인데, `ㄼ`을 만들려면 `ㄹ`+`ㅁ`(=ㄻ) 후 `*`로 ㅁ→ㅂ 가획 → `ㄼ`. 코어는 겹받침을 분해해 tail에 적용 후 재결합한다. 이 규칙이 없으면 `뱖` 같은 잘못된 글자가 나온다(초기 구현에서 실제 발생한 버그).

## 5. 상태 머신 정의

### 5.1 State

```
State {
  cho:       초성 (문자열, 빈값 가능)
  vstate:    모음 오토마타 상태
  jong:      종성
  last_key:  멀티탭 대상 키
  tap:       멀티탭 순환 인덱스
  snap:      멀티탭 시작 직전 상태 스냅샷
  committed: 확정 출력
  slot:      'cho' | 'jung' | 'jong'
}
```

### 5.2 스냅샷 기반 멀티탭 (핵심 설계)

멀티탭을 "현재 글자를 덮어쓰기"로 구현하면 겹받침에서 무너진다. `삶`을 칠 때 `ㄹ` 다음 `0`(ㅇ)을 누르면 `ㄹㅇ`은 겹받침이 아니므로 새 글자로 넘어가는데, 사용자가 `0`을 한 번 더 눌러 `ㅁ`을 의도했다면 이미 늦다.

해결: **멀티탭 시작 직전 상태를 스냅샷으로 저장**하고, 같은 키가 반복되면 스냅샷으로 되돌린 뒤 다음 순환 자모를 처음부터 결합한다.

```
press(s, key):
  if key는 자음키:
     if s.last_key == key and s.snap 존재:
        tap = (s.tap + 1) % 순환길이
        base = restore(s.snap)        # 되감기
     else:
        tap = 0; base = s
     snap = snapshot(base)
     return attach(base, 순환[tap])   # 처음부터 재결합
```

이 구조 덕분에 `삶`(`8125500`)에서 마지막 `00`이 `ㄹ`+`ㅇ`(새 글자 분리)을 취소하고 `ㄻ`으로 정확히 결합된다.

### 5.3 연음 처리 (도깨비불)

받침이 있는 상태에서 모음이 입력되면, 받침을 다음 글자의 초성으로 이동시킨다.

- `웃` + `ㅡ` + `ㆍ` → `우` + `스` → **`우슴`**... 이 아니라 `웃음`을 치려면 `03280300`
- 겹받침이면 **뒤 성분만** 이동: `앉` + `ㅏ` → `안` + `자`

검증된 동작:

| 입력 | 키 | 결과 |
|---|---|---|
| 고양이 | `42301220·01` | 고양이 |
| 웃음 | `03280300` | 웃음 |

### 5.4 백스페이스 — 자모 역추적

글자 단위가 아닌 **마지막 입력 1개만** 취소한다. 모음은 오토마타의 역방향 전이를 따른다.

| 입력 후 ⌫ | 결과 | 설명 |
|---|---|---|
| `4125⌫` | 가 | 각 → 가 (종성 제거) |
| `4231⌫` | 고 | 괴 → 고 (ㅣ 취소) |
| `4124·8⌫` | 각 | 갃 → 각 (겹받침 분해) |
| `44⌫` | (빈 값) | ㅋ → (빈 값) |
| `512⌫` | 니 | 나 → 니 (ㆍ만 취소) |

`512⌫` → `니`가 정답이다. `나`(ㄴ+ㅣ+ㆍ)에서 마지막 `ㆍ`만 취소되므로 `ㄴ+ㅣ` = `니`가 남는다. `ㄴ`이 되면 잘못된 구현이다.

## 7. 플랫폼별 통합 스펙

### 7.1 Windows — TSF (Text Services Framework)

- `ITfTextInputProcessorEx` 구현, `ITfComposition`으로 preedit 관리
- 조합 중 텍스트는 `ITfContext::GetStart` 범위에 밑줄 표시 속성 부여
- 키 이벤트: `ITfKeyEventSink::OnKeyDown`에서 숫자패드/일반 숫자키 매핑
- **주의**: TSF는 UWP·Win32 앱마다 컨텍스트 동작이 달라, `ITfContextOwnerCompositionSink::OnCompositionTerminated`에서 강제 커밋 처리 필수
- 레거시 IMM32 폴백 제공 (구형 앱 대응)

### 7.2 macOS — InputMethodKit

- `IMKInputController` 서브클래스, `inputText:client:` 오버라이드
- preedit는 `setMarkedText:selectionRange:replacementRange:`로 표시
- 확정은 `insertText:replacementRange:`
- `IMKCandidates`는 v1에서 미사용 (예측 입력 비목표)
- 샌드박스 및 공증(notarization) 필요

### 7.3 Linux — IBus

- `IBusEngine` 상속, `process_key_event` 시그널 처리
- `ibus_engine_update_preedit_text()` / `ibus_engine_commit_text()`
- Wayland/X11 양쪽 동작 확인 필요
- 패키징: `.deb` / `.rpm` / Flatpak

### 7.4 Android — InputMethodService

- `InputMethodService` + 커스텀 `KeyboardView`
- preedit: `InputConnection.setComposingText(text, 1)`
- 확정: `finishComposingText()` / `commitText()`
- 멀티탭 타이머: `Handler.postDelayed`, 기본 800ms (설정 가능)
- **주의**: 일부 앱(터미널, 게임)은 조합 텍스트를 지원하지 않으므로 `EditorInfo.TYPE_NULL` 감지 시 즉시 커밋 모드로 전환

### 7.5 iOS — Keyboard Extension

> **개정 (4단계)**: 이전 판은 "`UITextDocumentProxy`는 marked text API를 제공하지
> 않는다"는 전제로 delete-and-reinsert 우회를 규정하고 iOS를 v1.2로 미뤘다.
> **이 전제는 현재 사실이 아니다.** Apple 공식 문서 기준
> [`setMarkedText(_:selectedRange:)`](https://developer.apple.com/documentation/uikit/uitextdocumentproxy/setmarkedtext(_:selectedrange:))
> 와 `unmarkText()`는 **iOS 13.0+**에서 `UITextDocumentProxy`의 **Required** 멤버다.
> 근거가 됐던 자료는 2014년 iOS 8 시절 답변이었다.
> 따라서 iOS도 다른 플랫폼과 **동일하게 정식 preedit(밑줄 조합)**를 사용하며,
> v1.2 유예를 해제한다.

**기본 경로 — marked text (iOS 13+):**

```swift
proxy.setMarkedText(preedit, selectedRange: NSRange(location: preedit.count, length: 0))
proxy.unmarkText()   // 확정 시
```

시스템 한글 키보드와 동일하게 조합 중 밑줄이 표시된다. undo 스택 오염도 없다.

**폴백 경로 — delete-and-reinsert (iOS 12 이하):**

```
조합 글자가 바뀔 때마다:
  1. deleteBackward() × 직전에 삽입한 글자 수
  2. insertText(새 조합 글자)
```

두 경로는 `CompositionBridge`가 `supportsMarkedText`로 분기하며,
**11,172자 전수 대조로 동일한 최종 텍스트를 냄을 검증했다**(`ime/ios/run-tests.sh`).

- `RequestsOpenAccess`는 불필요 (네트워크·저장소 미사용) — 프라이버시 심사에 유리

**구현 주의 — 지연 확정:**
참조 구현은 멀티탭 되감기 시 `committed`까지 되돌린다(`갆` = `K4 K1 K2 K5 K8 K8`에서
5번째 키의 확정 `간`이 6번째 키로 취소된다). 브리지가 `committed`를 미리 가로채면
코어가 되돌릴 대상을 잃어 `간갆`처럼 깨진다(실제로 1,197자에서 발생). 멀티탭 세션이
살아 있는 동안에는 텍스트 필드로 내보내지 않고, 아직 안 보낸 몫만 조합 영역에 표시한다.

### 7.6 플랫폼 공통 계약

| 항목 | 규격 |
|---|---|
| 멀티탭 타임아웃 기본값 | 800ms (500–1500 설정 가능) |
| 타임아웃 주입 | 셸 → 코어에 `TIMEOUT` 키 |
| preedit 미지원 환경 | 즉시 커밋 모드 (조합 표시 생략) |
| 커밋 트리거 | 스페이스, 다른 글자 시작, 포커스 이동, 명시적 확정 |
