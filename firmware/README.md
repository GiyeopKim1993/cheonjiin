# 천지인 물리 키보드 펌웨어

16키 천지인 하드웨어 키보드용 임베디드 펌웨어. **하드웨어 비종속** 설계로,
새 보드 이식 시 HAL 함수 몇 개만 구현하면 된다.

## 계층 구조

```
┌─────────────────────────────────────────────┐
│  port/   보드별 진입점 + HAL 구현            │  ← 이식 시 여기만 작성
│          esp32 / stm32 / stm32f411 / rp2040  │
│          / sim                               │
├─────────────────────────────────────────────┤
│  hal/    cuime_hal.h — 인터페이스 정의 (5종) │  ← 계약. 수정 금지
├─────────────────────────────────────────────┤
│  app/    정책·타이머·레이아웃·한자 후보       │  ← 하드웨어 무관
├─────────────────────────────────────────────┤
│  core/   조합 엔진 (순수 상태기계, 시간 모름) │  ← 참조 구현과 전수 일치
│          cuime_tables.h = 자동 생성물         │
└─────────────────────────────────────────────┘
```

의존 방향은 **위에서 아래로만** 흐른다. core 는 HAL 을 모르고,
app 은 보드를 모르며, port 만 하드웨어를 안다.

## 검증

```bash
./build.sh
```

| 항목 | 결과 |
|---|---|
| 시뮬레이터 통합 (core+app+HAL) | ✅ 21 항목 |
| 보드 포트 정합성 esp32/stm32/rp2040 | ✅ 3/3 컴파일·링크·구동, 경고 0 |
| **STM32F411 실기기 데모** | ✅ 크로스 링크 + 정적 검증 + E2E 로직 검증 |
| 코어 전수 대조 — 멀티탭 11,172자 | ✅ 불일치 0 |
| 코어 전수 대조 — 롱프레스 11,172자 | ✅ 불일치 0 |

전수 대조는 JS/C++/Java/Python 참조 구현(MD5 `372100db…`)과 **완전 동일**함을
확인한 것이다. 펌웨어는 데스크톱 IME 와 한 글자도 다르게 동작하지 않는다.

## 새 보드 이식 방법

`port/<보드>/hal_<보드>.c` 하나만 작성한다. 구현할 함수는 5개 범주:

| 범주 | 함수 | 비고 |
|---|---|---|
| 키 스캔 | `hal_keys_init` `hal_keys_scan` | 16키 비트마스크. **디바운스는 HAL 책임** |
| 시간 | `hal_millis` `hal_delay_ms` | 밀리초 단조 증가 |
| 출력 | `hal_out_init/mode/ascii/unicode/special/connected` | HID 또는 유니코드 |
| 저장 | `hal_nvs_set_u32` `hal_nvs_get_u32` | 미지원 시 `false` 반환 허용 |
| 표시 | `hal_ui_preedit/layout/candidates/warn` | 화면 없으면 no-op 허용 |

그리고 `hal_board_init()` + 메인 루프에서 `cuime_app_poll()` 을 5ms 주기 호출.

이식 완료 여부는 크로스 컴파일러 없이도 확인할 수 있다:

```bash
gcc -std=c99 -Wall -Wextra -DCUIME_PORT_STUB -o /tmp/p \
    test/port_stub_main.c app/cuime_app.c core/cuime.c port/<보드>/hal_<보드>.c
```

링크가 성공하면 HAL 함수가 빠짐없이 구현된 것이다.

## 출력 모드

HID 키보드는 유니코드를 직접 보낼 수 없다. 그래서 두 가지 모드를 둔다.

- **`HAL_OUT_HID_DUBEOLSIK`** (기본) — 조합된 음절을 자모로 분해해
  **두벌식 자판 위치**의 키코드로 전송한다. 호스트의 한글 IME 가 음절로 합친다.
  일반 블루투스/USB 키보드로 인식되므로 드라이버 설치가 필요 없다.
  예: `가` → `r` `k`
- **`HAL_OUT_UNICODE_TEXT`** — 코드포인트를 그대로 전달. UART, BLE-UART,
  자체 앱 연동, 시뮬레이터용.

## 보드별 현황

| 보드 | 전송 | 상태 |
|---|---|---|
| ESP32 / S3 / C3 | BLE HID (ESP-IDF v5.x) | HAL 완성, 실기기 미검증 |
| STM32 F1/F4/L4 | USB HID (CubeMX) | HAL 완성, 실기기 미검증 |
| **STM32F411 Black Pill** | **UART UTF-8 / USB HID** | **플래시 가능한 `.bin`/`.hex` 산출. SDK 불필요** |
| RP2040 / Pico | USB HID (TinyUSB) | HAL 완성, 실기기 미검증 |
| POSIX 시뮬레이터 | 버퍼 | ✅ 검증 완료 |

GPIO 핀 번호와 `KEYMAP` 은 각 `hal_*.c` 상단에서 보드 배선에 맞게 수정한다.
기본값은 4×4 매트릭스(행 출력 / 열 풀업 입력) 기준이다.

> 실기기 검증은 크로스 컴파일러(`arm-none-eabi-gcc`, `xtensa-esp32-elf-gcc`)와
> 실물 하드웨어가 있어야 가능하다. 현재 환경에 없으므로 로직은 시뮬레이터로,
> 포팅 완결성은 STUB 링크로 검증했다.

### STM32F411 데모 — 실제로 구울 수 있는 바이너리

`port/stm32f411/` 은 위 표의 다른 포트들과 성격이 다르다. CubeMX HAL 에
의존하는 `port/stm32/` 와 달리 **레지스터를 직접 제어**해, 외부 SDK 없이
스타트업·링커스크립트까지 포함한 **완결된 펌웨어**를 만든다.

```bash
cd port/stm32f411 && ./build.sh      # -> build/cuime-f411.{elf,bin,hex}
st-flash write build/cuime-f411.bin 0x08000000
```

- 크기 **6,156 B** (Flash 512KB 의 1.17%), RAM 1,184 B
- 툴체인: `arm-none-eabi-gcc` 없으면 **zig** 로 자동 대체
- 검증 3단계: 크로스 링크 → 정적 검증(벡터/SP/thumb/SysTick/용량/심볼)
  → **호스트 로직 검증**(가짜 레지스터로 x86 에서 구동, `ㄱㅣㆍ␣`→`가 `
  같은 E2E 조합 포함)

자세한 배선도·클럭 설정·플래싱 방법은 `port/stm32f411/README.md` 참조.
여전히 **실물 보드 실측은 하지 않았다** — 정적 분석과 호스트 실행까지다.

## 테이블 재생성

`core/cuime_tables.h` 는 **자동 생성물이다. 직접 수정하지 말 것.**
참조 구현이 바뀌면 다시 생성한다:

```bash
python3 ../tools/gen_firmware_tables.py
```

손으로 옮기면 반드시 어긋난다 — 실제로 백스페이스 역추적 테이블(`CUIME_VPREV`)을
재구현했다가 `나`⌫ 가 `니` 대신 `내` 로 가는 버그를 겪었다. 생성기는 참조
구현의 `_PREV` 를 그대로 가져온다.

## 메모리

| 항목 | 크기 |
|---|---|
| 테이블 (`.rodata`, 플래시 상주) | 약 7 KB |
| `cuime_t` (코어 상태) | 약 40 B |
| `cuime_app_t` (앱 상태) | 약 120 B |

한자 사전은 포함하지 않는다. 필요하면 `app->hanja_lookup` 콜백으로 주입한다
(전체 사전은 약 700 KB이므로 외부 플래시 권장).
